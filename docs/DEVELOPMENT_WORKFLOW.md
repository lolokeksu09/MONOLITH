# NOX — регламент патчей, коммитов и документации

> Владелец проекта потребовал: **каждый патч = коммит(ы) в GitHub + актуальная документация**. Это обязательное правило для всех дальнейших версий.

## Одна единица работы — один проверяемый патч

1. **Контекст:** получить реальное состояние репозитория, основную ветку, актуальную feature-ветку, исходники и документацию. Зафиксировать base SHA. Новые версии развивать из согласованного актуального кода, не переписывая уже проверенные APK.
2. **Дизайн:** перед новым функционалом применить Development & Design Skills, согласовать объём изменений. Для новых архитектурных подсистем — документ спецификации и план. Не менять пользовательские решения молча.
3. **Тест:** добавить проверку, показывающую, что требуемое поведение отсутствует или нарушено; затем реализация; затем повторная проверка. Исправлять только подтверждённые ошибки.
4. **Документация:** вместе с исходниками обновить `docs/CHANGELOG.md`; при изменениях API, структур, интерфейса, сборки или совместимости также обновить соответствующие `README.md`, `docs/superpowers/specs/`, `docs/superpowers/plans/`. Для документов без исходного кода также нужен отдельный коммит.
5. **GitHub:** сделать осмысленный коммит на корректной ветке (например, `feat(scene): add aurora shader and catalog metadata`), опубликовать в GitHub, подтвердить конкретный SHA. Каждый следующий патч — отдельный коммит/цепочка коммитов, не незадокументированный промежуточный результат.
6. **Проверки:** запуск структурных тестов, JUnit/Gradle и Android CI для исходного кода. **Не считать APK готовым**, пока полный Android build не завершится и артефакт не проверен.
7. **Доставка:** в итоговом сообщении указать `branch`, `commit`, `docs changed`, `tests/CI status`, `APK` (если подтверждён), известные ограничения. Не обещать отложенную сборку или будущую доставку без реально настроенной автоматизации.

## Релизная дисциплина

- `main` на момент фиксации правил может содержать только раннюю версию NOX. Актуальные previews развиваются в feature-ветках. Не выполнять необдуманное слияние цепочки PR и не объявлять `main` актуальной без проверки.
- Соблюдать Offline-first, отсутствие root, AMOLED и pinned Studio preview.
- Перед изменением `SceneCatalog.ids`, `GlBackend` и экспорта `.nox` описывать миграцию/совместимость. Не терять и не молча преобразовывать старые сцены.
- DEBUG-пакет, подписанный другим ключом, не обновляет прежнюю установку. Не удалять старое приложение ради теста; перенос через собственный экспорт/импорт возможен только там, где он реализован.
- Документация **Draft/Planned** не означает реализованный код. Состояние `implemented`, `CI passed`, `tested on device` указывать отдельно и только после проверки.

## Минимальная запись в docs/CHANGELOG.md

```markdown
## [Версия] — статус (дата)
- Изменено: ...
- Проверено: ... (точные тесты / CI)
- Ветка / SHA: ...
- Совместимость / ограничения: ...
```

Это правило не заменяет планов и тестов, а делает их обязательной частью каждого патча.
