## Confirmed issues and disposition

| Area | Finding | Disposition |
| --- | --- | --- |
| Release metadata | `v0.10.0-beta.361` was published with a `MONOLITH 0.8.0 beta` title; CI also described an alpha APK. | Fix release title, notes, release-asset naming and version derivation for **future** builds. Historical releases remain unchanged. |
| Build versioning | Gradle and workflow held separate hard-coded release versions; disposable signing test still used `0.4.0-ci`. | Define the public beta version once in `gradle.properties`; reference it from Gradle and workflow. |
| README | Described a 0.7 release gate alongside 0.10 features; repeated widget support and left backup limitations scattered. | Replace with current capability inventory, installation safety and limitations. |
| Roadmap | Milestones stopped at 0.4 and mixed implemented ideas with proposed work. | Separate completed 0.1–0.10 features from pending quality work and optional theme-engine scope. |
| Dead legacy code | `PinnedAppsStore.kt` and its three tests exercised an unused pre-folder pin API. The real layout migration already reads the legacy preference in `HomeLayoutStore`. | Delete obsolete API/test and test the still-required legacy parser independently. |
| Architecture | `MonolithScreen.kt` has 1,331 lines; `MainActivity.kt` has 499 lines. The UI and activity are large and tightly coupled. | Record as technical debt. Avoid unverified, wide refactoring during repository cleanup. |
| Test coverage | 10 JVM test source files at baseline; no device/emulator UI test source present. | Retain CI and add a manual device acceptance checklist. |
| Signing | Stable release certificate SHA-256 is pinned in GitHub Actions and the secret key is not committed in the tracked tree. | Preserve certificate, package ID, key management and in-place update path. |

## Known risks still open

- No evidence from this audit that Android 16 Motorola gestures, keyboard window insets, widget binding/configuration, reboot and screen rotation work end to end.
- The HOME screen currently lacks a multi-page desktop, an internal theme engine and orbital app-menu animations.
- Import deliberately replaces the current layout; users should export a backup first. Android widget IDs are nonportable.
- A build passing GitHub Actions does not establish visual fidelity or on-device performance.

## Verification policy

For changes to UI or app behavior, require PR checks (`testDebugUnitTest`, `lintDebug`, `assembleDebug`, disposable signed release smoke) plus the relevant scenarios from `DEVICE_ACCEPTANCE.md`. Production signing on `main` must continue to verify the existing pinned certificate; do not rotate it during cleanup.
