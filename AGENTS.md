# NOX — обязательные правила разработки для AI-агентов и разработчиков

Этот файл применяется ко всем будущим изменениям проекта `lolokeksu09/NOX-LEGION`.

## Обязательное требование владельца: GitHub + документация ПОСЛЕ КАЖДОГО ПАТЧА

1. **Каждый завершённый патч обязательно фиксируй отдельным Git-коммитом в GitHub.** Никаких исключительно локальных или «готовых в чате» исправлений. Давай ссылку на коммит и использованную ветку. Не утверждай, что правка опубликована, если API GitHub не подтвердил SHA.
2. **В рамках каждого патча обновляй документацию, соответствующую изменению**: запись в `docs/CHANGELOG.md` (что изменено, версия, тесты, ограничения), при необходимости `README.md`, файл спецификации и/или план. Предпочтительно включать код, тесты и документацию в один коммит; допустим второй явно связанный документационный коммит в той же ветке. Не оставляй патч без документации.
3. До изменений проверяй фактическую ветку, HEAD, файлы и актуальные требования. **Не угадывай** ветки, имена файлов, команды, ссылки и статус CI.
4. Сначала тест, затем минимальное исправление/функция, затем повторная проверка. Если CI падает — читай логи, исправляй причину и снова коммить вместе с уточнением документации. Никогда не называй сборку успешной без подтверждения CI.
5. Для новых возможностей применяй `Development & Design Skills`; согласованные архитектурные спецификации храни в `docs/superpowers/specs/`, пошаговые планы — в `docs/superpowers/plans/`.
6. Не сливай feature-ветки в `main` автоматически. Для нового крупного релиза используй отдельную ветку и PR, пока владелец не утвердит интеграцию. Особенность истории: `main` может отставать от актуальных preview-веток.
7. Сохраняй нативный Kotlin/Compose, OpenGL ES, локальное хранение, работу без root и интернета, AMOLED-стиль NOX и **закреплённый предпросмотр Студии**. Любое изменение модели данных и совместимости файлов пресетов должно быть осознанно спроектировано и проверено.
8. APK — только после реальной компиляции и проверки конкретного артефакта. Debug APK из GitHub Actions может иметь новый ключ подписи: **не предлагай удалять рабочее приложение с приватными пресетами**. Отдельные preview-пакеты не разделяют данные автоматически.
9. По окончании каждого патча сообщай: что изменилось; ветка и SHA коммита(ов); какие документы изменены; какие тесты/CI действительно запускались и их результат; ссылку на APK, только если он проверен; что ещё требует тестирования на устройстве.

Подробный порядок: [docs/DEVELOPMENT_WORKFLOW.md](docs/DEVELOPMENT_WORKFLOW.md).

**Это постоянное правило репозитория, а не пожелание на один патч.**
